# Структура FSD

Пометка для других девелоперов

## Слои

- `app/` — роутинг, `layout`, `page` и глобальные стили
- `shared/` — переиспользуемый UI, общие стили и вспомогательные модули
- `features/` — пользовательские сценарии и локальная интерактивная логика
- `widgets/` — крупные UI-блоки, собранные из `shared`, `entities` и `features`
- `entities/` — предметные сущности проекта: пользователь, анализ, карточки дашборда и т.д.
- `processes/` — сквозные процессы между страницами и сценариями, если они появятся позже

## Что где лежит сейчас

- `shared/ui/button-back` — кнопка возврата
- `shared/ui/password-input` — переиспользуемые поля пароля для авторизации и регистрации
- `shared/ui/auth-shell` — общая оболочка и стили для auth-страниц
- `features/auth/*` — формы логина и регистрации
- `features/landing/scroll-to-section` — кнопка и логика прокрутки на лендинге
- `widgets/landing/*` — крупные блоки лендинга
- `widgets/account/*` — крупные блоки личного кабинета
- `entities/user` — модель пользователя, API и клиентский хук
- `entities/dashboard` — данные и UI карточек сводки
- `entities/analysis` — данные и UI строк анализа

## Правила

- `app/` остаётся точкой входа для маршрутов `Next.js`
- Импорты между слоями лучше вести через публичные `index.ts`, например `@/widgets/landing/header`
- Новую бизнес-логику лучше сразу раскладывать по слоям, а не возвращать в “общую” папку компонентов
- Если появляется устойчивая предметная модель, её лучше выносить в `entities/`

## Напоминалка для себя

Сейчас структура уже переведена на FSD-базу, но при росте проекта можно дополнительно:

- вынести навигацию и пункты sidebar в отдельные `entities`
- отделить mock-данные от UI в `model`-слой
- унифицировать нейминг компонентов и файлов, если появятся новые модули
